Как открыть лог-файл на 10 ГБ без зависаний

Notepad++ предупреждает, что файл больше 2 ГБ может открываться несколько минут, VS Code держит весь файл в памяти, и оба могут зависнуть на большом логе. BigText читает только то, что на экране, поэтому лог на 10 или 50 ГБ открывается сразу и занимает около 100 МБ памяти.

По шагам

  1. Откройте его

    Через «Файл → Открыть», перетаскиванием в окно или командой bigtext app.log в терминале (bigtext app.log:120 откроет на 120-й строке). Логи в .gz и .zst открываются напрямую.

  2. Перемещайтесь

    Ctrl+End сразу переходит к последней строке. Переход к строке (Ctrl+G) работает ещё до окончания индексации; до тех пор номера строк идут со знаком ~. Переход ко времени (Ctrl+Shift+T) принимает 14:32:05 и ставит на первую строку с этим временем.

  3. Найдите ошибки

    Панель уровней над логом фильтрует строки ERROR, WARN, INFO и DEBUG, а F8 переходит к следующей ошибке. Ctrl+F ищет по всему файлу, в том числе по регулярным выражениям, «Найти все» показывает список совпадений.

  4. Оставьте только нужное

    Режим фильтра показывает только совпадающие строки или, наоборот, только несовпадающие — как grep по всему файлу — и сохраняет их в новый файл.

  5. Следите вживую

    Режим слежения (bigtext -f app.log или «Следить за файлом (tail)» в палитре команд) добавляет новые строки как tail -F и переживает ротацию логов. Лог на сервере открывается по SSH с вашими ключами: bigtext -f user@server:/var/log/syslog.

Полезно знать

  • Несколько логов можно объединить по времени в одно окно или прокручивать два лога вместе по времени.
  • Поиск, фильтр и сохранение идут в фоне с индикатором и кнопкой отмены, окно не перестаёт отвечать.
