Extract one table from a mysqldump file

A full mysqldump of a database can be tens of gigabytes, and often you need one table from it: to restore it, to check its data or to send it to someone. BigText opens the dump at once without loading it into memory, and Export lines… writes any range of lines to a new file.

Step by step

  1. Open the dump

    Open the .sql file with File → Open or by dragging it onto the window. A .sql.gz dump opens directly too.

  2. List the tables

    mysqldump marks each table with a comment such as -- Table structure for table `orders`. Search for -- Table structure for table and press Find All: the results list every table in the dump with its line number.

  3. Find where the table starts and ends

    Click the table you need in the results; its line number is in the status bar. The next table's comment is where it ends: F3 jumps to it.

  4. Write it to a file

    File → Export lines… writes a range of lines to a new file: from the first line of the table to the line before the next table. You get a small .sql file with the CREATE TABLE statement and the table's INSERT lines.

Good to know

  • The dump starts with SET lines (character set, foreign key checks). Copy them to the top of the new file if the table needs them.
  • A dump made with --skip-comments has no such comments: search for CREATE TABLE `orders` and the next DROP TABLE IF EXISTS instead.
  • Only the data: the filter view with INSERT INTO `orders` shows just that table's INSERT lines and saves them to a new file.
