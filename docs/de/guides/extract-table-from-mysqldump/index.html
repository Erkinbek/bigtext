Eine Tabelle aus einer mysqldump-Datei herauslösen

Ein vollständiger mysqldump einer Datenbank kann Dutzende Gigabyte groß sein, und oft brauchen Sie nur eine Tabelle daraus: um sie wiederherzustellen, ihre Daten zu prüfen oder sie weiterzugeben. BigText öffnet den Dump sofort, ohne ihn in den Speicher zu laden, und „Zeilen exportieren…“ schreibt einen beliebigen Zeilenbereich in eine neue Datei.

Schritt für Schritt

  1. Den Dump öffnen

    Öffnen Sie die .sql-Datei mit Datei → Öffnen oder ziehen Sie sie auf das Fenster. Ein .sql.gz-Dump öffnet sich ebenfalls direkt.

  2. Die Tabellen auflisten

    mysqldump markiert jede Tabelle mit einem Kommentar wie -- Table structure for table `orders`. Suchen Sie nach -- Table structure for table und drücken Sie „Alle suchen“: Die Ergebnisse listen jede Tabelle des Dumps mit ihrer Zeilennummer.

  3. Anfang und Ende der Tabelle finden

    Klicken Sie in den Ergebnissen auf die gesuchte Tabelle; ihre Zeilennummer steht in der Statusleiste. Sie endet dort, wo der Kommentar der nächsten Tabelle beginnt: F3 springt dorthin.

  4. In eine Datei schreiben

    Datei → Zeilen exportieren… schreibt einen Zeilenbereich in eine neue Datei: von der ersten Zeile der Tabelle bis zur Zeile vor der nächsten Tabelle. Sie erhalten eine kleine .sql-Datei mit der CREATE-TABLE-Anweisung und den INSERT-Zeilen der Tabelle.

Gut zu wissen

  • Der Dump beginnt mit SET-Zeilen (Zeichensatz, Fremdschlüsselprüfung). Kopieren Sie sie an den Anfang der neuen Datei, wenn die Tabelle sie braucht.
  • Ein Dump mit --skip-comments hat diese Kommentare nicht: Suchen Sie stattdessen nach CREATE TABLE `orders` und dem nächsten DROP TABLE IF EXISTS.
  • Nur die Daten: Die Filteransicht mit INSERT INTO `orders` zeigt nur die INSERT-Zeilen dieser Tabelle und speichert sie in eine neue Datei.
